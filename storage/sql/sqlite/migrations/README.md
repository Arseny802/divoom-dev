# Миграции схемы SQLite

Каталог для инкрементальных изменений схемы базы данных. Базовая схема v1
находится в [`db.sql`](../db.sql) и применяется автоматически при первом
открытии пустой БД (`PRAGMA user_version == 0`).

## Как добавить новую миграцию

1. Создайте файл с именем `NNNN_<описание>.sql`, где `NNNN` — следующий номер
   версии (например, если текущая версия `1`, новый файл будет
   `0002_add_something.sql`).
2. Внутри файла опишите только *инкрементальное* изменение схемы. Используйте
   `IF NOT EXISTS` / защитные проверки, чтобы миграция была идемпотентной.
3. В конце файла обязательно увеличьте версию:
   ```sql
   PRAGMA user_version = 2;
   ```
   (и при необходимости обновите `meta.schema_version`).
4. Зарегистрируйте скрипт в [`sql_resources.cpp`](../../src/sql_resources.cpp):
   - добавьте строку эмбеддинга `INCBIN(sql_migration_0002, STORAGE_SQL_DIR "/sql/sqlite/migrations/0002_add_something.sql");`
   - добавьте запись `{2, make_string(gsql_migration_0002Data, gsql_migration_0002Size)}`
     в список `migrations()`.

> **Важно.** Файлы SQL хранятся в исполняемом файле через `incbin` и применяются
> миграционным раннером в рамках одной транзакции. Порядок применения — по
> возрастанию номера версии.

## Правила

- Никогда не редактируйте уже применённую миграцию — создавайте новую.
- Каждая миграция должна быть совместима как с SQLite-бэкендом, так и
  концептуально отражена в `json_backend` (файловое хранилище просто зеркалит
  модель данных БД).
